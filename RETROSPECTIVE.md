# FlyRank AI Internship — Retrospective

When I started the FlyRank AI internship in Week 1, my main goal was to build practical skills in Artificial Intelligence and Machine Learning and understand how to turn ideas into useful working projects. I wanted to become more comfortable with building, testing, documenting, and presenting technical work rather than only learning concepts theoretically.

During the internship, my approach gradually changed from simply completing individual assignments to thinking more about the complete workflow behind a project. I learned that building something useful is not only about writing code. It also involves defining the problem, making clear design decisions, testing real behavior, documenting the work, and communicating what was built.

One important part of my work was the Personal Study and Internship Planner Agent. I built a simple Python-based agent that reads structured tasks from a JSON file and recommends what should be worked on first. The current implementation uses priority levels such as High, Medium, and Low. I tested the agent with study tasks and confirmed that the High-priority Operating Systems task was recommended first. Building this project helped me understand the importance of keeping an initial version simple enough to test and explain clearly.

Another major part of my internship work was improving my portfolio website. I developed the portfolio to present my projects, skills, internship experience, and contact information. I then added a working contact form using Formspree so that the website could perform a real dynamic function. I tested the form with different inputs, including empty fields and invalid email formats, and also completed a successful real submission. This taught me that a feature should be tested with both normal and incorrect inputs instead of assuming that it works because the code looks correct.

I also improved the portfolio with SEO metadata, Open Graph information, a favicon, Google Analytics, and a FlyRank credential badge. During testing, I noticed that the FlyRank credential verification page displayed a “No public credential found” message even though the badge itself was displayed correctly and linked to the verification page. I documented this as an external verification issue instead of making an unnecessary change to the website code.

One thing that changed for me was my understanding of iteration. Earlier, I might have considered a project finished once it worked once. During this internship, I became more aware that working software should be tested, reviewed, documented, and improved. Small changes such as adding validation, improving documentation, or explaining limitations can make a project much more useful and understandable.

If I continued building the Personal Study and Internship Planner Agent, I would add deadline-aware prioritization, workload estimation, dependency and blocker detection, automatic task breakdown, and calendar integration. These improvements would make the agent more useful than the current priority-only implementation.

The three most transferable things I learned are:

1. Build a simple working version first and improve it through iterations.
2. Test real behavior, including failure cases, instead of relying only on the code.
3. Documentation and communication are part of engineering, not separate from it.

Overall, the internship helped me move from thinking mainly about individual assignments to thinking about practical projects as complete systems. I became more comfortable with building, testing, documenting, and explaining my work, and I now have a clearer idea of how I would continue improving the projects I started.
